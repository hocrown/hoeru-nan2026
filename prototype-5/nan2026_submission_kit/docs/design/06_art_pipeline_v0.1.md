# 아트 파이프라인 v0.1 — AI 활용 전략과 툴 선정

> 2026-08-10 / 대상: 캐릭터 일러스트(스토어·스토리 연출용) + 인게임 에셋(픽셀 스프라이트·타일·이펙트)
> 전제: 픽셀 아트 톤 가정 (세피리아·산나비 계열). 2D 일러스트 톤으로 갈 경우 §6 참조.

---

## 1. 결론 요약

1. **일러스트(고해상도)와 인게임 픽셀 에셋은 파이프라인을 분리한다.** 범용 생성 모델은 일러스트·컨셉에는 강하지만, 게임에 바로 넣을 수 있는 정격 픽셀 스프라이트(고정 그리드·제한 팔레트·프레임 일관성)에는 부적합.
2. **AI는 컨셉·탐색·초벌, 마감은 사람 손.** 특히 애니메이션 프레임 일관성과 히트박스가 걸린 스프라이트는 최종적으로 Aseprite 수작업 폴리시 필수.
3. **캐릭터 일관성은 '레퍼런스 시트 → 고정 참조 생성' 워크플로로 확보.** 매번 프롬프트로 새로 뽑지 말 것.
4. **Steam AI 고지 의무를 처음부터 계획에 반영.** (§5)

## 2. 단계별 파이프라인

```
① 아트 디렉션 보드 (스타일 확정)
   범용 모델로 무드보드 대량 생성 → 톤 확정 (수공 픽셀 레퍼런스 병용)
② 캐릭터 마스터 시트 (버전별 3면도 + 표정)
   무영 A/B/C 3버전 등 — 고해상도 일러스트. 이후 모든 생성의 '고정 참조'
③ 파생 일러스트 (스토리 컷, 인연록 초상, 스토어 아트)
   ②를 참조 이미지로 걸고 생성 → 일관성 유지
④ 픽셀 변환 (인게임 스프라이트)
   ②/③를 입력으로 픽셀 특화 툴에서 스프라이트·애니메이션 초벌 생성
⑤ 수작업 폴리시 (Aseprite)
   팔레트 정리, 실루엣 보정, 프레임 타이밍, 히트박스 기준 정렬
⑥ 타일셋·배경·이펙트 (별도 트랙, 동일 원칙)
```

## 3. 툴 비교

### 3-1. 일러스트·컨셉 (①~③단계)
| 툴 | 강점 | 유의점 |
|---|---|---|
| **Google AI Studio (Gemini 이미지 계열)** | 참조 이미지 기반 캐릭터 일관성·부분 수정(자연어 편집)에 강함. 공유해주신 앱도 이 계열로 추정 | 상용 이용 약관·해상도 확인 필요. 앱 링크는 로그인 필요로 미확인 — 용도 공유 요망 |
| **Grok (Imagine)** | 빠른 탐색·무드보드 대량 생성 | 스타일 고정·시리즈 일관성 통제력은 상대적으로 약함. 상용 라이선스 조항 확인 필요 |
| **Midjourney** | 스타일 일관성 기능(스타일/캐릭터 참조)과 품질. 아트 디렉션 보드 최강급 | 유료. 무협 톤은 프롬프트 튜닝 필요 |
| **Stable Diffusion + ComfyUI (+LoRA)** | 무료·로컬·통제력 최고. 자체 스타일 LoRA 학습으로 프로젝트 고유 톤 고정 가능 | 학습 곡선 큼. GPU 필요. 모델별 라이선스 확인 |
| **Scenario 등 게임 특화 SaaS** | 프로젝트 전용 커스텀 모델 학습 → 팀 전체가 동일 스타일로 생성 | 구독 비용 |

### 3-2. 픽셀·스프라이트 (④단계)
| 툴 | 강점 | 유의점 |
|---|---|---|
| **Retro Diffusion** | 픽셀 아트 특화 생성(정격 그리드·팔레트), Aseprite 연동 워크플로 | 복잡한 액션 프레임은 초벌 수준 |
| **PixelLab (Aseprite 플러그인)** | 스프라이트 회전·애니메이션 보간 등 실작업 밀착 기능 | 최종 품질은 수작업 병행 전제 |
| **웹 기반 스프라이트 시트 생성기** (PixelBox, SpriteFlow 등 다수) | 참조 이미지 → 걷기/공격 등 프리셋 애니메이션 시트 자동 생성. 프로토타입 속도 | 품질 편차 큼. 프로토타입·검증용으로 한정 권장, 본편 투입 전 반드시 폴리시 |
| **Aseprite (수작업)** | 최종 마감의 표준 | — |

### 3-3. 용도별 권장 조합
- 프로토타입(재미 검증): 웹 스프라이트 생성기 + Retro Diffusion으로 속도전. 품질 무시.
- 수직 슬라이스~본편: ②마스터 시트(Midjourney 또는 Gemini 계열) → ④Retro Diffusion/PixelLab 초벌 → ⑤Aseprite 마감. 핵심 캐릭터(무영, 도윤, 동행)는 마감 비중 상향.
- 물량 에셋(신수·요괴·잡졸 수십 종): 스타일 고정된 커스텀 모델(LoRA/Scenario)로 배치 생성 → 일괄 팔레트 정리.

## 4. 캐릭터 일관성 실무 수칙

1. 캐릭터당 **마스터 시트 1장** (3면도+표정)을 먼저 확정하고, 이후 모든 생성은 이를 참조 이미지로 첨부.
2. 프롬프트에 고정 서술 블록 사용 (아래 §7 시드). 매번 새로 쓰지 말 것.
3. 실루엣 우선: 픽셀 축소 시 살아남는 형태(무영: 장검 1자루 + 겉옷 라인)를 시트 단계에서 검증 — 시트를 64px로 강제 축소해보는 테스트.
4. 팔레트 사전 확정: 게임 전체 팔레트(예: 32색)를 먼저 정하고 생성물에 강제 매핑.

## 5. 법률·플랫폼 리스크 (필독)

1. **Steam AI 고지 의무**: 스팀은 게임 등록 시 AI 콘텐츠 설문을 요구하며, '사전 생성'(아트·사운드·텍스트 등)과 '라이브 생성'을 구분해 사용 방식을 공개해야 하고 스토어 페이지에 고지 섹션이 노출된다. 고지 없이 사용하다 적발되면 논란·제재 리스크 (실제 사례 존재). → **숨길 생각을 버리고, 고지 문구를 마케팅 톤과 함께 미리 설계할 것.**
2. **저작권**: 미국 기준, AI 단독 생성물은 저작권 보호를 받지 못하며 인간의 창작적 기여분에 한해 보호 가능. → 핵심 아트일수록 인간 가공(리페인트·리터치) 비중을 높이는 것이 IP 보호 관점에서도 필요.
3. **툴별 상용 라이선스**: 각 툴의 상용 이용 조건·학습 데이터 정책을 채택 전 확인. 특히 무료 티어는 상용 불가인 경우 다수.
4. **여론 리스크**: 스팀 코어 유저층 일부의 AI 아트 백래시 존재. 핵심 비주얼(키 아트, 주요 캐릭터)은 사람 마감 품질로 방어하는 것이 안전.

## 6. 아트 톤 결정 대기 사항

- 픽셀(세피리아·산나비 계열) vs 2D 일러스트 계열 — 미정. 본 문서는 픽셀 전제.
- 픽셀 선택 시 해상도 급 결정 필요: 저해상도(32~48px 캐릭터, 물량 유리) vs 고해상도 픽셀(산나비급, 연출 유리·비용 증가). 뱀서식 물량 게임 특성상 **저해상도 + 연출 씬만 고해상도 일러스트** 하이브리드 권장.
